# Кросспостинг Telegram → MAX

Автоперенос постов из канала **Telegram** в канал **MAX**: опубликовал в Telegram — через пару секунд то же самое появилось в MAX. Со всей разметкой, видео, кружками и альбомами.

Работает в проде на канале онлайн-школы с июля 2026.

---

## Что переносится

| Что | Как доезжает |
|---|---|
| Текст, эмодзи, переносы строк | как есть |
| **Жирный, курсив, подчёркнутый, зачёркнутый, моноширинный** | сохраняется |
| Ссылка словом (гиперссылка) | сохраняется **вместе с URL** |
| Пост длиннее 4000 символов | режется по границе абзаца на несколько сообщений |
| Фото, фото с подписью | одним сообщением |
| Видео | одним сообщением |
| Кружок (video note) | квадратным видео — кружков в MAX нет |
| Гифка | видео |
| Голосовое | вложением-файлом — MAX не принимает ogg/opus |
| Аудио, документы | как есть |
| Альбомы: фото, видео, фото+видео | **одним** сообщением, с фолбэком по одному |
| Опрос | вопрос и варианты текстом — опросов в API MAX нет |
| Inline-кнопки со ссылками | настоящей клавиатурой MAX |
| Правка поста в Telegram | правит то же сообщение в MAX |

Каждый пункт проверен живым прогоном 25 тестовых постов, а не «по документации».

**Чего не будет** (ограничения MAX, а не проекта): стикеры (не принимает webp), спойлер и цитата теряют оформление, у репоста нет плашки «переслано из».

## Как работает

```
TG-канал ──channel_post──▶ бот-читатель через ЛОКАЛЬНЫЙ Bot API
                                  │  скачивание (локальный сервер нужен для видео >20 МБ)
                                  ▼
                        перезалив в MAX: /uploads → token → /messages
                                  ▼
                             MAX-канал
```

Два контейнера: локальный Telegram Bot API и Python-воркер (aiogram + httpx). Дедуп постов в sqlite — рестарт не задваивает, а пропущенное пока воркер лежал догоняется.

## Быстрый старт

Нужны Docker с Compose и пять минут.

**1. Бот в Telegram.** [@BotFather](https://t.me/BotFather) → `/newbot` → добавить бота **администратором** в канал-источник с правом читать сообщения.

**2. Бот в MAX.** [dev.max.ru](https://dev.max.ru) → создать бота → добавить **администратором** в канал-приёмник с правом публикации.

**3. `api_id` и `api_hash`** — на [my.telegram.org](https://my.telegram.org). Нужны локальному Bot API, без него не скачать видео больше 20 МБ.

**4. Настроить и запустить:**

```bash
git clone https://github.com/RakushkaTOP/telegram-to-max-crossposter.git
cd telegram-to-max-crossposter
cp .env.example .env
# заполнить .env, затем:
docker compose up -d --build
```

**5. Узнать ID каналов.** Опубликуйте в канале-источнике любой пост и посмотрите лог:

```bash
docker compose logs -f worker
```

Строка `источник вне маршрутов: chat_id=-100… title='…'` покажет ID канала Telegram. ID канала MAX виден в адресе `web.max.ru/-77463…`. Подставьте их в `.env` и перезапустите.

## Настройка

| Переменная | Зачем |
|---|---|
| `TG_BOT_TOKEN` | токен бота-читателя от @BotFather |
| `TG_SOURCE_CHAT_ID` | ID канала-источника, например `-1001234567890` |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | с my.telegram.org, для локального Bot API |
| `MAX_TOKEN` | токен бота MAX |
| `MAX_CHAT_ID` | ID канала-приёмника в MAX |
| `MAX_API_BASE` | по умолчанию `https://platform-api2.max.ru` |
| `ROUTES` | несколько пар каналов сразу, см. ниже |
| `ALBUM_DEBOUNCE_MS` | сколько ждать сборки альбома, по умолчанию 1500 |

### Несколько каналов одним ботом

```env
ROUTES=-1001111111111:-72111111111,-1002222222222:-72222222222
```

Пара из `TG_SOURCE_CHAT_ID`/`MAX_CHAT_ID` работает всегда, `ROUTES` её дополняет.

Так же удобно держать тестовую пару каналов рядом с боевой. Запускать **второй экземпляр воркера с тем же токеном нельзя**: два поллинга на один токен дерутся за `getUpdates`, и рабочий перенос встанет.

## Грабли MAX API

Собрано опытным путём — в документации этого нет.

- **Токен вложения приходит по-разному.** Для `video` и `audio` он лежит уже в ответе `/uploads`, а сама заливка на CDN отвечает `<retval>1</retval>` — даже не JSON. Для `image` и `file` наоборот: токен только после заливки. Если искать его лишь в ответе заливки, **ни одно видео не доедет**, и в логах будет тишина.
- **Лимит текста — 4000 символов**, у Telegram 4096. Пост между этими значениями теряется целиком: `Field 'text' size (4090) must be at most 4000`.
- **Разметка — только через `format: "html"`.** Свои entities MAX не принимает, `b/i/u/s/a/code` превращает в `strong/emphasized/underline/strikethrough/link/monospaced`. Смещения entities Telegram считает в **UTF-16 code units** — режьте строку по байтам `utf-16-le`, иначе первый же эмодзи развалит разметку.
- **`chat_id` — только query-параметр.** В теле JSON приходит `400 proto.payload "Unknown recipient"`.
- **Авторизация — только заголовок** `Authorization: <token>`, query-параметр задепрекейчен.
- **Видео обрабатывается асинхронно:** сразу после загрузки отправка отвечает `400 attachment.not.ready` — это «подожди», а не ошибка. Воркер ретраит до 12 раз.
- **Аудио — только mp3/wav/m4a.** Голосовые Telegram (ogg/opus) отбиваются `415`, поэтому уходят файлом.
- **Не больше 3 кнопок-ссылок в ряд**, иначе MAX отвергает сообщение целиком.
- **Правка (`PUT /messages`) не сносит вложения** — можно править только текст, не перезаливая медиа.
- **Домен переезжал дважды:** `botapi.max.ru` → `platform-api.max.ru` → `platform-api2.max.ru`. Последний подписан **корневым сертификатом Минцифры РФ**, которого нет ни в обычных образах, ни в наборе `certifi`, — без него TLS падает с `unable to get local issuer certificate`. Сертификаты лежат в `worker/certs/` и ставятся при сборке образа в оба хранилища сразу: системное (для aiogram) и certifi (для httpx, он системное игнорирует).

## Эксплуатация

```bash
docker compose logs -f worker        # что происходит
docker compose ps                    # живы ли контейнеры
docker compose up -d --build         # выкатить правку
```

| В логе | Что это значит |
|---|---|
| `upload body failed 415` | MAX не принял формат файла |
| `attachment.not.ready` | видео ещё обрабатывается, воркер ждёт сам |
| `альбом … не принят … раскладываю по одному` | пачку отвергли, сработал фолбэк |
| `Unknown recipient` | сломалась адресация `chat_id` |
| `источник вне маршрутов` | пост из канала, которого нет в `ROUTES` |

Важные детали, которые легко сломать при доработке:

- Очередь апдейтов сбрасывается **только на первом старте** (когда база дедупа пуста). На рестартах сброс потерял бы посты, вышедшие пока воркер лежал.
- Скачанные файлы удаляются после перезалива: локальный Bot API свой том **никогда** не чистит, канал с видео забьёт диск.
- `TG_BOT_TOKEN` **нельзя** дёргать через `api.telegram.org` — бот перелогинится в облачный Bot API, и локальный начнёт отдавать 401 (лечится `POST /logOut`).
