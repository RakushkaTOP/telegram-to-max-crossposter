# crossposting-tg-max

Авто-перенос постов из канала **Telegram** в канал **MAX**. Пересобран с нуля
2026-07-27 (предыдущая версия жила на VDS `2.27.10.248`, который стёрли —
исходник и `.env` утеряны вместе с ним).

## Как работает
```
TG-канал ──channel_post──▶ бот (@vastu_syncbot) через ЛОКАЛЬНЫЙ Bot API
                                   │ download (видео >20 МБ — потому и локальный сервер)
                                   ▼
                          перезалив в MAX (/uploads → token → /messages)
                                   ▼
                              MAX-канал
```
Два контейнера: `crosspost-bot-api` (локальный Telegram Bot API, `--local`) и
`crosspost-tg-worker` (Python/aiogram + httpx). Альбомы собираются с дебаунсом,
дедуп постов — в sqlite (`/data/crosspost.db`), рестарт не задваивает.

## Запуск
1. `cp .env.example .env` и заполнить: `TG_BOT_TOKEN`, `TG_SOURCE_CHAT_ID`,
   `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`, `MAX_TOKEN`, `MAX_CHAT_ID`.
2. Бот TG — админ канала-источника; бот MAX — админ канала-приёмника.
3. `docker compose up -d --build`
4. Логи: `docker compose logs -f crosspost-tg-worker`

## Прод
Развёрнут в `/opt/crossposting-tg-max` на Hetzner `62.238.27.80` (там же
телеграм-бот школы). Порт наружу не публикуется, всё по внутренней сети compose.

## Статус
В проде с 2026-07-27. Текстовая ветка подтверждена живым тестом (TG → MAX за
178 мс). Фото/видео/альбомы написаны и защищены ретраями, но вживую ещё не
прогонялись — проверяются на реальных постах канала.

## Особенности MAX API (проверено на живом сервере)
- Авторизация — **только** заголовок `Authorization: <token>`. Query-параметр
  `access_token` задепрекейчен: `401 verify.token`.
- `chat_id` — **только** query-параметр. В теле JSON приходит
  `400 proto.payload "Unknown recipient"`. Отсюда `MAX_CHAT_ID_IN_QUERY=true`
  (дефолт; при отказе `send()` сам пробует второй способ и запоминает рабочий).
- Видео обрабатывается асинхронно: сразу после `/uploads` отправка отвечает
  `400 attachment.not.ready` — воркер ретраит до 12 раз с растущей паузой.
- Форма ответа `/uploads` (`token` vs `photos.*.token`) разобрана в
  `max_client._extract_token`; при новой форме смотреть лог `upload body:`.
- Если `/messages` или `/uploads` дадут 404 — сменить `MAX_API_BASE` на
  `https://platform-api2.max.ru` (на 2026-07-27 этот хост не отвечает).

## Эксплуатация
- Очередь апдейтов сбрасывается только на первом старте (пустая база дедупа);
  на рестартах пропущенное догоняется, дубли отсекает sqlite.
- Скачанные Bot API файлы удаляются после перезалива — иначе его том растёт
  бесконечно и забивает диск хоста.
- `TG_BOT_TOKEN` нельзя дёргать через `api.telegram.org`: бот залогинится в
  облачный Bot API и локальный начнёт отдавать 401 (лечится `POST /logOut`).
