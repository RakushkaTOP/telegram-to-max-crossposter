# MAX Bot API: что переносится и на какие грабли мы наступили

Справка для тех, кто хочет понять, как проект устроен внутри, или пишет свою интеграцию с MAX. Всё ниже проверено живыми запросами, а не по документации.

## Полная таблица переносимости

| Что в Telegram | Как доезжает в MAX |
|---|---|
| Текст, эмодзи, переносы строк | как есть |
| Жирный, курсив, подчёркнутый, зачёркнутый, моноширинный | сохраняется (`format: html`) |
| Ссылка словом | сохраняется вместе с URL |
| Пост длиннее 4000 символов | режется по границе абзаца на несколько сообщений |
| Фото, фото с подписью | одним сообщением |
| Видео | одним сообщением |
| Кружок (video note) | квадратным видео — кружков в MAX нет |
| Гифка | видео |
| Голосовое | вложением-файлом — MAX не принимает ogg/opus |
| Аудио, документы | как есть |
| Альбомы: фото, видео, фото+видео | одним сообщением, при отказе — по одному |
| Опрос | вопрос и варианты текстом — опросов в API MAX нет вообще |
| Inline-кнопки со ссылками | настоящей клавиатурой MAX |
| Правка поста | правит то же сообщение в MAX |
| Стикеры | не переносятся (MAX не принимает webp) |
| Спойлер, цитата | текст доезжает, оформление теряется |
| Репост | обычным постом, без плашки «переслано из» |

## Грабли MAX API

- **Токен вложения приходит по-разному.** Для `video` и `audio` он лежит уже в ответе `POST /uploads`, а сама заливка на CDN отвечает `<retval>1</retval>` — даже не JSON. Для `image` и `file` наоборот: токен только в ответе заливки. Если искать его лишь в ответе заливки, ни одно видео не доедет.
- **Лимит текста — 4000 символов**, у Telegram 4096. Пост между этими значениями отвергается целиком: `Field 'text' size (4090) must be at most 4000`.
- **Разметка — только через `format: "html"`.** Свои entities MAX не принимает. Теги `b/i/u/s/a/code` превращаются в `strong/emphasized/underline/strikethrough/link/monospaced`. Смещения entities Telegram считает в **UTF-16 code units** — резать строку надо по байтам `utf-16-le`, иначе первый же эмодзи сдвинет разметку.
- **`chat_id` — только query-параметр.** В теле JSON приходит `400 proto.payload "Unknown recipient"`.
- **Авторизация — только заголовок** `Authorization: <token>`; `access_token` в query задепрекейчен (`401 verify.token`).
- **Видео обрабатывается асинхронно:** сразу после загрузки отправка отвечает `400 attachment.not.ready` — это «подожди», а не ошибка. Воркер ретраит до 12 раз с растущей паузой.
- **Аудио — только mp3/wav/m4a.** ogg/opus отбивается `415`.
- **Не больше 3 кнопок-ссылок в ряд**, иначе MAX отвергает всё сообщение.
- **Правка (`PUT /messages?message_id=`) не сносит вложения** — можно править текст, не перезаливая медиа.
- **Домен переезжал дважды:** `botapi.max.ru` → `platform-api.max.ru` → **`platform-api2.max.ru`** (актуальный с 19.07.2026). Новый хост подписан **корневым сертификатом Минцифры РФ**, которого нет ни в докер-образах, ни в наборе `certifi` — без него TLS падает с `unable to get local issuer certificate`. Причём положить сертификат в системное хранилище мало: `httpx` системные CA игнорирует и ходит со своим набором. В этом проекте сертификаты (`worker/certs/`, публичные, с gu-st.ru) ставятся при сборке образа в оба места: системное — для aiogram, certifi — для httpx.

## Инварианты воркера (легко сломать при доработке)

- Очередь апдейтов Telegram сбрасывается **только на первом старте** (когда база дедупа пуста). На рестартах сброс потерял бы посты, вышедшие пока воркер лежал; от дублей защищает sqlite.
- Скачанные файлы удаляются сразу после перезалива: локальный Bot API свой том **никогда** не чистит, канал с видео забьёт диск.
- Токен бота-читателя **нельзя** дёргать через облачный `api.telegram.org` — бот перелогинится туда, и локальный Bot API начнёт отдавать 401 (лечится `POST /logOut` на облачном).
- Альбомы собираются скользящим дебаунсом: каждый новый кадр отодвигает отправку, иначе большой альбом рвётся на два поста.
- Соответствие «пост Telegram → сообщение MAX» хранится в sqlite (таблица `sent`) — без него правку поста не к чему применить.
