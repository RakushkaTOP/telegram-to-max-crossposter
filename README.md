# Кросспостинг Telegram → MAX

Опубликовал пост в Telegram-канале — через пару секунд он сам появился в канале MAX. Разметка, видео, альбомы и кнопки доезжают, вести две площадки руками больше не нужно.

Работает в проде на канале онлайн-школы с июля 2026.

## Что умеет

- Текст с разметкой: жирный, курсив, зачёркнутый, моноширинный, ссылки словом
- Фото, видео, кружки, гифки, голосовые, документы
- Альбомы (фото, видео, смешанные) — одним сообщением
- Кнопки под постом — настоящей клавиатурой MAX
- Правка поста в Telegram правит его и в MAX
- Длинные посты (>4000 символов) режутся аккуратно, по абзацам
- Несколько пар каналов одним ботом

Подробная таблица «что и в каком виде доезжает» и ограничения MAX — в [docs/max-api.md](docs/max-api.md).

## Шаг 1. Подготовь три вещи

| Что | Где взять |
|---|---|
| Токен Telegram-бота | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `api_id` и `api_hash` | [my.telegram.org](https://my.telegram.org) → API development tools |
| Токен бота MAX | [dev.max.ru](https://dev.max.ru) → создать бота |

После создания добавь Telegram-бота **администратором** в канал-источник, бота MAX — **администратором** в канал-приёмник (с правом публикации).

## Шаг 2. Установи

### Вариант А — скрипт (Linux-сервер, рекомендую)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RakushkaTOP/telegram-to-max-crossposter/master/install.sh)
```

Скрипт сам проверит Docker (предложит поставить, если нет), скачает код, спросит токены и запустит контейнеры. Повторный запуск той же команды = обновление до свежей версии, настройки сохраняются.

### Вариант Б — вручную (любая система с Docker)

```bash
git clone https://github.com/RakushkaTOP/telegram-to-max-crossposter.git
cd telegram-to-max-crossposter
cp .env.example .env
# заполни .env своими токенами, затем:
docker compose up -d --build
```

## Шаг 3. Укажи каналы

Не знаешь ID своих каналов? Это нормально, воркер сам подскажет:

1. Опубликуй в Telegram-канале любой пост
2. Посмотри лог: `docker compose logs -f worker`
3. Строка `источник вне маршрутов: chat_id=-100…` — это ID твоего Telegram-канала
4. ID канала MAX виден в адресной строке: `web.max.ru/-77…`
5. Впиши оба в `.env` (`TG_SOURCE_CHAT_ID` и `MAX_CHAT_ID`) и перезапусти: `docker compose up -d`

Готово. Опубликуй пост — он появится в MAX.

## Несколько каналов

Одним ботом можно вести сколько угодно пар «Telegram → MAX»:

```env
ROUTES=-1001111111111:-72111111111,-1002222222222:-72222222222
```

Боты должны быть админами во всех каналах пары. Второй экземпляр воркера с тем же токеном запускать нельзя — два поллинга подерутся за обновления; для новых каналов используй `ROUTES`.

## Полезные команды

```bash
docker compose logs -f worker    # живой лог
docker compose ps                # статус контейнеров
docker compose up -d --build     # выкатить обновление кода
```

## Если что-то не доехало

| В логе | Что значит |
|---|---|
| `источник вне маршрутов` | канал не вписан в `.env` / `ROUTES` |
| `attachment.not.ready` | MAX ещё обрабатывает видео — воркер дождётся сам |
| `upload body failed 415` | MAX не принял формат файла |
| `Unknown recipient` | неверный `MAX_CHAT_ID` |

Больше диагностики и все грабли MAX API — в [docs/max-api.md](docs/max-api.md).
